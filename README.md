# えひめAEDレスキューマップ

**AEDの場所を探す地図ではなく、AEDが届きにくい人口を探し、「次の1台」を考える地図。**

愛媛県オープンデータカタログ／松山市オープンデータで公開されている実データを組み合わせ、AEDの短時間アクセス圏、推計未カバー人口、75歳以上の推計未カバー人口、追加1台によるカバー人口最大化を可視化する静的WebアプリのPoCです。

## デモ機能

- 松山市AEDを地図表示
- アクセス半径を150〜600mで変更
- 「全AED」と「24時間利用可と保守的に判定したAED」を切替
- 推計カバー率／未カバー人口／75歳以上未カバー人口を再計算
- 未カバー需要点を地図表示
- 公共施設を候補地点として「次の1台」の追加カバー人口を総当たり最大化
- 未カバー人口の地域ランキング
- GitHub Pagesでサーバーレス公開

## 使用データ

| データ | 主な用途 | データ時点 | 出典 |
|---|---|---|---|
| AED設置箇所一覧 | AED位置・利用可能日時 | 2025-03-01 | 松山市 / 愛媛県オープンデータカタログ |
| 地域・年齢別人口 | 総人口・75歳以上人口 | 2026-04-01 | 松山市 / 愛媛県オープンデータカタログ |
| 公共施設一覧 | 需要点プロキシ・配置候補 | 2024-02-20 | 松山市 / 愛媛県オープンデータカタログ |

直接取得URLは `scripts/build_data.py` の `SOURCE_META` に固定しています。原典CSVはGitへ複製せず、CI / GitHub Pagesのビルド時に松山市公式URLから取得して `data/processed.json` を生成します。

## 「4分圏」の定義

初期値は **直線距離300m** です。これは一般利用者に直感的な「徒歩約4分相当」を見せるPoC上の近似であり、AED取得・往復時間や医学的な救命限界を保証するものではありません。UIから150〜600mに変更できます。本番化する場合は、直線距離ではなく歩行道路ネットワークの到達時間へ置き換えるべきです。

## 人口カバレッジのPoCモデル

松山市の地域・年齢別人口は44地域単位ですが、地域ポリゴンや個々の居住点の緯度経度を持ちません。そのため初版で虚偽の精密さを出さないよう、次の透明なプロキシを採用しています。

1. 44地域の代表点を原則として各地域の公民館位置から取得。
2. 公共施設を最寄り地域代表点に割り当て。
3. 各地域の人口・75歳以上人口を、その地域に割り当てられた公共施設位置へ均等配分。
4. その「需要点」とAEDの直線距離でカバレッジを計算。

忽那諸島の4地域（睦野・東中島・西中島・神和）は、公開公共施設の所在地から代表点を派生しています。

このモデルは政策判断の確定値ではなく、**オープンデータのみで1〜2日で意思決定型PoCを成立させるための推計モデル**です。

## 「次の1台」の最適化

配置候補は松山市公共施設一覧から作ります。ただし既存AEDから50m未満の施設は候補から除きます。

設定半径 `r` に対して、候補施設 `c` ごとに未カバー需要点の人口を加算し、追加カバー人口が最大の候補を推薦します。同点時は75歳以上の追加カバー人口が大きい候補を優先します。

## 初期実データQA（2026-08-23実行）

- 人口: 490,710人
- 75歳以上: 84,664人
- AED: 671件
- 24時間利用可判定: 74件
- 地域: 44
- 需要点: 764
- 追加設置候補: 539
- 300m・全AEDの推計カバー率: 約69.9%
- 300m・全AEDの推計未カバー人口: 約147,773人

数値は元データ更新時に変化します。

## ローカル起動

```bash
python scripts/update_data.py
python scripts/qa.py
python -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。

## QA

```bash
python scripts/update_data.py
python -m unittest discover -s tests -v
python scripts/qa.py
node --check assets/app.js
```

GitHub Actionsでは公式CSVを取得して同じ検証を実行します。原典の取得不能・スキーマ変更・分析不変条件違反はCI失敗として検知します。

## GitHub Pages

`.github/workflows/pages.yml` はmainへのpush時に、公式CSVを取得 → `processed.json`生成 → QA → Pages artifact作成 → Deployを行います。

リポジトリの **Settings → Pages → Source** が **GitHub Actions** になっていれば公開できます。
